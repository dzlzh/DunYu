# 界面切换诊断包

解压到可写目录，双击 `run-ui-diagnostics.cmd`，按提示开始。不需要安装 Rust。测试使用临时配置、两条虚构规则，不保存用户配置、不注册全局快捷键。不要同时运行其他遁鱼测试。

先运行缓冲区检查和三次独立进程的导航验证，再采样约 20～60 秒，图片保存可能需要更长时间，自动切换六页、规则、高级选项、主窗口隐藏恢复及休憩卡片/全屏画面。让测试窗口保持可见、无遮挡，期间不要操作电脑。多屏测试会短暂出现全屏休憩画面，随后自动关闭。请留出数 GB 磁盘空间；原始 BMP 体积较大。

完成后将最新 `ui-diagnostics-*` 文件夹和 `diagnostic-run.log` 压缩提供给开发者。目录内包含：

- `summary.txt`：无截图干扰的一轮操作耗时 p50、p95、最大值。
- `report.json`：构建版本、Windows 版本、DPI、窗口尺寸、每次操作时间线、布局和自绘回调累计耗时/次数（不含原生控件内部绘制）、采样时间戳、缺口和可疑帧。
- 各场景目录：实际桌面像素的连续 BMP，不通过 PrintWindow 或强制重绘生成。

诊断会保存测试窗口内实际显示的内容。遮挡检测在复制像素前后执行，遇到遮挡、超出桌面或采样内存上限会记录缺口；避免在采样时移动其他窗口。隐藏窗口期间无画面属于预期，不能据此声称画面验证通过。每个场景最多保留 128 MiB 像素，完整高 DPI、多屏采样可能超出预算。

`white_block` 表示暗色界面的大块亮色区域；高对比模式不执行这一判断。`suspected_mixed_frame` 表示画面与同窗口、同尺寸的首尾帧均明显不同，只作为人工复核候选，焦点、动画等正常变化也可能触发。无异常标记不代表没有闪烁：采样目标间隔为 16 ms，加上复制耗时后实际间隔更长，需查看时间戳和采集结束时间。连续帧间隔超过 32 ms 会记录采样缺口。窗口打开、关闭和改变尺寸时，端点不完整，必须结合逐帧图片复核。

计时轮在采样轮之前运行。操作调用实际应用方法并正常分发窗口消息，但不模拟物理鼠标输入；`handler_ms` 不等同于输入到屏幕显示的延迟。布局/绘制的计时包含在调用时间中时不能重复相加。首次访问指测试准备后的首次访问，不是应用冷启动。此诊断包尚不提供自动的“无花屏”结论。

开发者在 Windows 构建诊断包：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/package-ui-diagnostics.ps1
```

产物为 `target/DunYu-ui-diagnostics.zip`。CI 在 Windows 构建并上传同名诊断 artifact；交互诊断测试默认忽略，不在无人值守 CI 桌面执行。普通应用二进制不包含诊断模块或计时探针。

修复版追加 `paint.surface/tab/brand/heading/control/rest`、`paint.draw/copy` 和 `buffer.allocate` 计数。它们是嵌套计时，不与 `paint` 求和。`buffer.allocate` 只记录尺寸变化或首次分配；重复同尺寸绘制应复用资源。

静态场景固定焦点及鼠标位置，`mixed_static_content` 忽略导航和页脚，只检测内容区。检测到亮块或静态拼接候选时，先保存全部报告与图片，再令测试失败；候选仍需复核。正常隐藏阶段的无窗口记录标为 `expected`，其余覆盖缺口仍需检查。采样器也识别暂停重绘期间仍留在屏幕上的旧画面。

在同一机器上与原报告比较性能：

```text
python scripts/compare-ui-diagnostics.py OLD/report.json NEW/report.json
```

只比较无截图干扰的暖态切页（索引 6～17）。目标是 handler p95 降低至少 30%，自绘累计 p95 不退化；报告显示目标是否达到。此比较不会自动判定视觉合格。程序自身恢复窗口时会同步绘制完整画面，采样器不会额外强制重绘。

导航优化版在采样之前运行导航缓存的原生像素对照测试；失败时保留日志并停止。测试覆盖六页、焦点、DPI、尺寸、字体和主题失效，不修改系统高对比度设置。高对比度模式需另行人工检查。

新增 `paint.tab.cache_build/cache_copy/active/icon/text`，分别记录未选中项缓存重建、复制、选中项、图标、文字绘制；仍是嵌套计时，不能求和。缓存只保留每项当前几何状态，高对比度模式绕过缓存。

使用 `python scripts/compare-ui-diagnostics.py OLD/report.json NEW/report.json --goal navigation` 比较导航优化：同环境暖态导航绘制 p95 降低至少 50%，累计自绘 p95 降低至少 20%，handler p95 不超过基线的 110%。缺少导航指标不能通过该目标；默认比较目标保持原行为。

资源检查修正版先验证缓冲区同尺寸复用、尺寸替换和最终释放，再执行导航像素对照。释放验证通过仅测试构建启用的实例观察器，检查恢复原位图、`DeleteObject` 和 `DeleteDC` 的实际结果，不查询已释放句柄的 `GetObjectType`。窗口销毁失败、缓存析构未执行、具体释放调用失败会分别报错；检查失败仍停止后续采样。正式程序不包含释放观察器。

退出流程修正版使用控制台测试程序。测试窗口、图形缓存、GDI+ 和字体在线程返回前清理；`Navigation checks completed` 只说明检查部分完成，仍须等待清理日志、测试框架结果和进程零退出码。每个阶段的 `STAGE_START/STAGE_END` 包含 UTC 时间、状态和原始退出码。资源预检及每次导航验证限时 120 秒，采样限时 600 秒；超时只终止该阶段由脚本启动的测试进程，返回 124，保留已写入报告并停止后续阶段。

双击入口通过系统 Windows PowerShell 运行随包的 `run-ui-diagnostics.ps1`，不要只复制 exe/cmd。`diagnostic-run.log` 汇总各阶段 stdout、stderr 和退出结果；两种流分段汇总，不表示跨流的精确时间顺序，原始内容另存为各阶段 `.stdout.log/.stderr.log`。失败时请一并提供这些日志。启动提示为 START，失败为 FAILED，全部进程正常结束为 COMPLETED；只有最后一种表示脚本完整跑完，视觉和性能验收仍需检查报告。

启动器回归自检（无需显示测试窗口）：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run-ui-diagnostics.ps1 -SelfTest`。它验证正常退出、打印成功文字后非零退出、stderr 保留以及超时终止；Windows CI 执行该检查。

导航裁剪修正版保持界面尺寸不变，缓存未选中项的纵向可见区域。像素对照覆盖 51/52/70px 高度和四档 DPI，并要求重复绘制命中五个未选中项。三次对照之后新增 `navigation-real` 阶段，使用真实设置窗口验证单列、双列布局的像素一致、缓存命中和暖态无分配。

每个场景追加 `navigation_geometry`（客户区、原始项矩形、可见交集、高对比度状态）；`paint.tab.fallback.*` 区分高对比度、无缓冲、空交集、横向裁剪及 GDI 复制/存储失败。普通模式下，无截图暖态切页没有缓存命中会记录 `navigation_cache_failures`，保存报告后使测试失败。高对比度仍走原绘制路径。已有退出日志和清理检查保持有效。

原测试机器的既定导航目标仍为：暖态导航绘制 p95 ≤ 11.13 ms、自绘累计 p95 ≤ 32.94 ms、handler p95 ≤ 8.03 ms。原生像素测试通过不代表性能或视觉覆盖自动达标。

## 第二轮性能诊断（performance-v2）

高级选项和规则切换的页面准备在计时前完成；规则切换不再额外执行一次布局。新报告带计时协议版本，不能与旧协议自动比较通过。`rest.close/create/font/show_and_paint` 是嵌套计时，不相加；显示和同步绘制完成不代表已经上屏。

A/B 包包含 `dunyu-ui-baseline.exe` 和优化版 `dunyu-ui-tests.exe`。基线来自提交 `1a026fd`，仅加入当前诊断协议与计时探针。生成方法：`python scripts/build-performance-baseline.py`（交叉构建可加 `--target x86_64-pc-windows-gnu`），然后用 `scripts/package-ui-diagnostics.ps1 -Baseline target/dunyu-ui-baseline.exe` 打包。Python 仅供构建者使用，用户运行诊断无需安装 Python。

启动器先验证缓冲区、导航、休憩局部绘制和静态控件像素，再采样优化版；随后交替运行基线和优化版，各三个独立进程。每进程测试十二次暖态切页、本进程首次全屏、十次暖态全屏开启、十次卡片转全屏以及五秒动画（包含每秒状态更新）。首次使用不等于应用冷启动。动画画笔层仍保持原有绘制顺序，装饰笔触不合入静态底图，以免改变与鱼重叠的像素。

`benchmark-baseline-*.json`、`benchmark-candidate-*.json` 保存原始阶段计数和逐次绘制耗时。`performance-comparison.json` 汇总目标：卡片转全屏 p95、动画绘制 p95、动画 CPU 中位数降低至少30%；绘制次数不低于基线90%；首次开启中位数和暖态开启 p95 不超过基线110%。切页目标仍为8.03/11.13/32.94ms。任何未达标项都明确为 false；完成运行不代表性能或视觉全部通过。

运行期间保持窗口可见、无遮挡。请提供 `diagnostic-run.log`、全部 `benchmark-*.json`、`performance-comparison.json` 和新 `ui-diagnostics-*` 文件夹。高对比度、关闭动画或跨次显示器配置不一致时，比较器拒绝给出性能结论。Windows 原生像素测试和 PowerShell 脚本需要 Windows 验证；交叉构建不替代它们。


## 休憩像素差异诊断版

缓冲区检查后立即执行休憩像素对照，限时600秒；通过后再执行导航、截图和原有 A/B 流程。使用隐藏测试窗口验证1920×1080、1672×941、3440×1440和1080×1920，不改变显示器分辨率。测试固定动画时间与状态；每种尺寸分别检查0、333、999毫秒下的参考重复绘制、缓存整帧首次构建、缓存整帧重复使用、无缓存局部重绘、缓存局部重绘，共60个案例。此版本不修改生产绘制和性能协议。

每次运行创建独立的 `rest-pixel-diagnostics-*` 目录。`report.json` 每完成一个案例就更新，记录尺寸、DPI、时间点、缓存计数、不同像素数量、最大通道差、首个差异和差异包围框（右/下边界不包含在内）。像素失败保存 `actual.bmp`、`reference.bmp`、`diff.bmp`，差异图以洋红色标出不一致位置。忽略alpha但要求RGB完全一致；全部案例收集后仍以非零退出码阻止后续阶段。`complete=false` 表示采集或资源检查未完成，不能视作通过。

若仍失败，请提供 `diagnostic-run.log`、`rest-pixels.stdout.log`、`rest-pixels.stderr.log` 和整个新 `rest-pixel-diagnostics-*` 目录；无需额外执行命令。Windows CI 普通测试会验证差异统计和BMP输出；实际休憩对照仍需Windows实机运行。


## 休憩坐标一致性修复版

休憩后台绘制固定使用客户区坐标，脏矩形只限制更新与提交范围。局部静态缓存由现有整帧后台位图上的背景和圆环截取得到，避免以局部原点重新采样；尺寸或主题改变后重建，缓存不可用时使用无缓存路径。

保留原有60项严格RGB对照，并在四种尺寸分别追加小矩形、交叠、空区域、完全越界、部分越界及主题失效重建，共84项。裁剪对照使用黑色目标底图，参考路径只裁剪最终提交，检查区域外未被覆盖。失配仍保存三张BMP和报告，并阻止后续性能阶段。A/B基线、协议和性能门槛不变；通过交叉编译不代表Windows原生像素检查通过。


## 休憩交叠裁剪修复版

有后台缓冲时，GDI/GDI+绘制裁剪固定为完整客户区，避免小矩形切入游鱼时改变采样结果。背景恢复与缓存复制仍只处理脏区域，最终仅将脏区域复制到窗口，并保留窗口原有裁剪。后台区域外的临时像素不提交，后续更新前先恢复背景；无后台缓冲时保留直接绘制的目标裁剪。

保留84项像素检查；四种尺寸各增加第二矩形单独绘制（0ms）、A→B→A和B→A→B（分别0/333/999ms）三项，共96项。序列双方从黑色目标开始，参考侧每步绘制完整帧并只提交相同矩形，检查区域外保持原样、交叠区没有累积残影。JSON中`expected_cases`为96，`measurements[].steps`记录矩形和逐步时间；RGB仍须完全一致，失败保存图片且阻止后续阶段。原A/B基线和性能门槛保持不变。
